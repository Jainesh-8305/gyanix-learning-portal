# Gyanix Learning Portal - project implementation report

Gyanix is a college learning portal built with Next.js, React, Express and MongoDB. It supports separate student, instructor and administrator workflows and free enrollment in published courses. This report describes the current implementation; use the latest QA report for executed test results and remaining limitations.

Students join courses/classroom batches, watch lessons, save progress, submit assignments, view private feedback, practise quizzes, save study notes, review persistent SuperMemo-2 flashcards and earn project completion certificates after passing assessments. Instructors build curricula, submit for approval, manage course resource hubs and classroom quizzes, inspect owned enrollments and manually grade submissions. Administrators moderate publication, manage account activation and inspect enrollment records. Payment gateways, checkout, course pricing and revenue reporting have been removed.

All three dashboards use a consistent professional workspace layout with clear navigation, spacing, summaries and focused tools. Large modals, gradebooks and quiz data load on demand. The student overview uses one aggregate endpoint; shared user data is not cached across identities. Global background/cursor animation loops and expensive glass filters have been removed, while reduced-motion preferences are respected.

The assistant is a small floating icon available on relevant signed-in pages. It supports private account/role-owned conversation history, configurable response language and source links. Retrieval combines reviewed role-tagged help articles, local multilingual keyword ranking, optional semantic embeddings and ownership-filtered account summaries. A configured OpenAI Responses model enables natural multilingual conversation. No-key/provider-failure mode explicitly shows retrieved help articles rather than pretending a language model answered.

Backend permissions filter retrieval before generation. User-supplied roles, account IDs, histories and arbitrary document/URL choices are not trusted. Students cannot retrieve another student's private notes/submissions, instructors cannot inspect another instructor's course data, and non-admins cannot retrieve administrator-only help. The assistant cannot change access, submit work or execute administrator actions. Passwords, API keys and assessment reference keys are excluded from its context.

Security controls include private reset tokens, token-version revocation, no public seeding, field/ownership validation, draft moderation, server-owned timed attempts, validated progress, backed certificate verification without account email, assignment deadlines/grade ranges and per-account API limits. Automated tests exercise these boundaries and meaningful negative cases. Mocked provider tests verify request assembly; actual language quality requires configured provider testing and cannot be inferred from mocks or an offline article.

There is no automatic model training, Claude/Gemini synthesis, video transcription, external academic accreditation or autonomous permission-changing agent. Offline draft content requires review. SMTP inbox delivery and Cloudinary uploads need credentials and separate live checks. Changes remain local until explicitly committed, pushed and deployed.
